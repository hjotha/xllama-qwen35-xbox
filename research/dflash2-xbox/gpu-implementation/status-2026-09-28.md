## Causes and measured bottleneck

Q2/Q3 kernels launched 256 threads although their CPU-compatible accumulation
needed at most 64. Reducing the group and sharing decoded weights improved the
Q3 warm DRAFT from about 110 ms to 59.75 ms while preserving tested outputs.
The reduction in overall generation time is measured in the table above.

Package .70 GPU timestamps for a short Q3 batch of five total 59.071 ms:
FFN down projection 28.4568 ms; FFN gate/up 17.1175 ms; grouped attention output
and convolution 6.7623 ms; grouped QKV/norm/RoPE 4.26594 ms. Attention itself is
0.42498 ms at this short context. In real generation, target verification adds
45.331064 ms/cycle and selector 4.904256 ms/cycle. RPC elapsed time already
includes Xbox compute and must not be added to it a second time.
[Profile](parity-gpu-70-20260928/q3-profile.json).

## Numerical reference and verified scope

The reference is the actual llama.cpp CPU graph and its MSVC AVX2/FMA/repack
execution on Xbox. The unmodified CPU reproduced all 369 frozen Q3 F0 frames
bit for bit. It is an operational parity reference, not an independent
Hugging Face/PyTorch model validation.

BeeLlama includes the upstream DFlash2 implementation (merge `63cb21324`,
llama.cpp #27342, and encoder fusion `662a0b012`). Its Xbox RPC split is a local
integration and must still be validated independently of those upstream merges.
Primary references: [upstream DFlash2 pull request](https://github.com/ggml-org/llama.cpp/pull/27342),
[upstream graph](https://github.com/ggml-org/llama.cpp/blob/master/src/models/dflash.cpp),
[model reference](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2).

Corrections made in this work include CPU-compatible Q2/Q3/Q4/Q5 accumulation,
RMS normalization, RoPE constants, dynamic-convolution rounding, AVX2 SwiGLU,
online attention and the UCRT expf implementation. A 1,048,576-sample expf
fingerprint matched on both HPBEATS and Xbox. The historical AGY GPU-to-GPU
identity check did not establish CPU parity; its earlier CPU comparison failed.

Package **1.0.0.75** passes the full **369-frame replay for both Q2 and Q3**,
with byte-identical status/header/output (timing fields excluded), plus all
40 short comparisons across batches 2, 3, 5, 7 and 8 with maxAbs=0.
[Q2 full replay](parity-gpu-final-20260928/q2-full-replay-75.json),
[Q3 full replay](parity-gpu-final-20260928/q3-full-replay-75.json),
[Q2 short cases](parity-gpu-final-20260928/q2-all-75.json),
[Q3 short cases](parity-gpu-final-20260928/q3-all-75.json).

The last Q3 error was one Q4 KV byte (layer 3 V, position 226). Running the
CPU packer on the **same GPU Hadamard output** reproduced the CPU byte, proving
that the packer itself differed. Explicit F32 rounding of `x + 8.5` before
integer truncation fixed it; the DXIL had used fast addition followed by integer
conversion. Correcting the reciprocal alone had not fixed it. No reference,
fixture whitelist or tolerance was relaxed.
[Before](parity-gpu-final-20260928/sync-boundary-before-fix-74.json),
[after](parity-gpu-final-20260928/sync-boundary-75.json).

The KV probe now includes `nextafter(2.5f, 0.0f) + 8.5f`, which must round to 11
before truncation. Hardware KV and attention probes pass, as do all six trim
protocol cases including 64-row reset and invalid-request preservation.
Build .75 and five Python unit tests pass. Package hash and selected source
hashes are recorded in the [manifest](parity-gpu-final-20260928/manifest.json).

Q4 down-projection was subsequently changed from 256 to 128 threads while
preserving separate 64-element integer groups and the CPU FMA order. Q5 keeps
256 threads. On Xbox .74 this reduced warm batch-five DRAFT from 59.76 to
58.73 ms, with exact short outputs; FFN down fell from 28.457 to 27.497 ms.
The fixed .75 then passed the complete Q2/Q3 replays.

## Improvements and plan gates

- Improvement 1: parameter sweep implemented; AGY demonstrated 30.109 tok/s
  with greedy sampling. The current comparison preserves those parameters.
  The planned 85% acceptance / 4 tokens per cycle goal is not established.
- Improvement 2: opcode 18 combines SYNC and DRAFT into one RPC and passed
  equivalence smoke tests. SYNC and DRAFT still have separate GPU submissions;
  one-command-list/fence fusion is not complete.
- Improvement 3: implemented on .57 and tested with real Xbox D3D12. Both
  observed pre-draft attempts were discarded, no prefetched result was used,
  and the guard disabled further attempts. No performance benefit was measured.
  It is off by default; this test explicitly set `DFLASH_XBOX_PIPELINE=1`, and
  startup logs confirm it was enabled. The implementation can promote a
  pre-draft only when exactly one token was accepted. These attempts accepted
  four and two tokens, so they were discarded before position/token matching.
  The guard then disabled it after two attempts and zero reused drafts.
  [Pipeline evidence](agy-replay-gpu-75-20260928/pipeline-evidence.json).

F0 CPU replay and F1 hardware execution are demonstrated. F2 has corrected
kernels and targeted profiles, but its complete repetition matrix has not been
rerun. F3/F4 now have exact full Q2 and Q3 replays, all supported DRAFT batch sizes
and selected state/protocol tests. The full SWA/context boundary matrix is still pending. F5 integration is exercised, but complete fault injection
and leak/recovery campaigns are pending. F6 has pilots only and has not shown
an advantage over target-only generation. F7 thread/kernel optimization has
measured gains.

The 128-token greedy runs agree with target-only output. At 512 tokens, the
sequential and pipelined outputs agree with each other but differ from
target-only output. Token/logit tracing of target verification and rollback is
still required before claiming full generation equivalence.

After the .75 campaign, Xbox remained on `d3d12` with `dflash-q3.gguf` and the
.57 production service was restored active with a successful health response.
Further work requested: Q2 with `n_max=7`, separate/fused RPC comparison and
pipeline review. These pending experiments do not change the parity results above.
