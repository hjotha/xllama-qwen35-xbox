# patches/

UWP/AppContainer patches against the pinned `llama.cpp` submodule, applied to
both build variants that compile ggml (`uwp/ggml-uwp.vcxproj`): the shipping
`unified` variant (`XLLAMA_USE_ORT=1` + `XLLAMA_USE_LLAMA=1`) and the bench-only
`llamacpp` variant. CI runs `scripts/apply-uwp-patches.sh` for both, which
applies every `patches/0*-*.patch` in order and is idempotent per patch.

| `0002-kv-mixed-fault-parse-options.patch`    | `fault()` takes the options type as a template parameter. The `kv_mixed_file_backing` ctor reports through `parse_options` and `stream_serialize` through `stream_options`; with a single `stream_options` overload the whole `#if !defined(__linux__)` block fails to compile with C2664 on every non-Linux platform. Found by the UWP build of the beellama fork (`ggml-uwp.vcxproj`), not by the Linux host build — the offending code is excluded there.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `0003-remote-attn-aligned-alloc-win32.patch` | Aligned 64-byte host allocation on Win32 in **2 files**: `ggml-remote-attn.cpp` and `ggml-local-split.cpp` use `posix_memalign` unconditionally, which MSVC does not have (C3861). `local-split` gets `aligned_alloc_64` / `aligned_free_64` helpers for its 12 sites; `remote-attn` gets an inline `_WIN32` branch for its single buffer. **Free is patched too**: the MSVC CRT requires `_aligned_free` on `_aligned_malloc` memory and `free()` on it is undefined behaviour, so fixing only the allocation would trade a compile error for heap corruption. Neither file's allocation is reached unless the remote-attn / local-split backends are selected, which the Xbox build never does.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `0004-export-mtp-embedding-apis.patch`       | Make the MTP APIs callable from outside the fork, in **3 files**. Two defects, both invisible until an out-of-tree caller tried to link. **(1) Linkage mismatch**: `llama_set_embeddings_nextn`, `llama_get_embeddings_nextn_ith`, `llama_get_ctx_other` and `llama_model_mtp_weights_get_info` are declared in `src/llama-ext.h` with `LLAMA_API` and read as C, but nothing forced C linkage, so both toolchains compiled the definitions with C++ mangling and an `extern "C"` caller looked for the plain name and found only `_Z26llama_set_embeddings_nextn...`. **(2) Missing export**: the same definitions carried no `LLAMA_API`, so on ELF they were absent from the shared library even by mangled name. Both fixed by marking exactly these eight lines `extern "C"` + `LLAMA_API`, declaration and definition alike. **Scope is deliberately narrow**: `llama-ext.h` cannot be wrapped at file scope because other entry points there return `std::map` / `std::vector`, and C2526 rejects C linkage on C++ return types. Harmless inside the fork's own `common` library. Required by the MTP frontend in this repo.    |
| `0005-cpu-repack-force-gemv-control.patch`   | Diagnostic-only opt-in control in `ggml/src/ggml-cpu/repack.cpp` for the z-0 first-divergence investigation. One shared predicate gates BOTH activation quantization and compute (they cannot drift). `GGML_REPACK_FORCE_GEMV=1` scopes it to the exact z-0 gate matmul (`blk.0.attn_gate.weight`, Q4_K 2560x4096); `=2` scopes it to every repack matmul at small diagnostic widths (nrows ≤ 8, measured probe for the same nrows>3 mechanism at other weights). Forced path = scalar-row activation quantization + scalar gemv tail for all rows — exactly the already-running B3 sequence, never blocked-quantized data under a scalar reader — instead of blocked quantization + blocked GEMM. Strict env parse (exactly "1"/"2"; anything else = off), so a typo cannot widen scope. Prefill/chunks keep the optimized path, so staged prefixes and their asserts are unaffected. One atomic-capped WARN line per engaged shape (race-free). Default off (env absent/empty/0); no behavior change otherwise. NOT a performance solution. Set from `cpurepackforcegemv.txt` (content "1" or "2") by the xllama diagnostic runners. |

Patch `0006-cpu-flash-attn-consistent-kv-reduction.patch` adds the exact opt-in
`GGML_FLASH_ATTN_NO_SPLIT_KV=1`. It disables only the single-query split-KV
branch, retaining parallelism across heads and the existing prefill tiling.
The ordinary single-query and MTP multi-query paths then use the same reduction
order. `flashattn.txt=2` selects this experimental control at UWP startup;
absent/0 leaves native behavior unchanged. The long-prompt token166 trace in
`bench/results/fast-mtp-20261007/` records the motivating argmax drift.

Patch 0001 was rebased onto the current `982eaadaa` pin on 2026-10-07, so
its remaining mmap/mlock guards apply directly in a shallow checkout.
Other patches retain their maintained contexts. Patch 0002 was retired because
upstream `ggml/src/ggml-cpu/ops.h` now uses fixed cache-line sizes and no longer
references `std::hardware_destructive_interference_size`; there is no matching
code left to patch. The CPU backend remains statically linked on UWP.

## Applying

```bash
./scripts/apply-uwp-patches.sh   # idempotent; used by the llamacpp CI variant
```

## Rebasing after a submodule bump

The patch is a plain `git diff`. If it no longer applies, redo the three guards
by hand (they are one-liners plus a small `#if` block — see the patch body) and
regenerate with `git -C llama.cpp diff > patches/0001-uwp-appcontainer-guards.patch`.
