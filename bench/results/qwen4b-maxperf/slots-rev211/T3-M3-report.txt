## Findings (bounded to tested prompts)

1. Harvest-free rebuild WORKS: zero carry + tail catch-up replays enough
   mirror for drafting to engage the same turn (drafted>0 every arm).
2. Acceptance ≈ full-harvest method: 88% vs 85% (64tok), 81% vs 81%
   (151tok), rounds/decodes/discarded nearly identical (20/88/23 vs
   21/89/21). Carry row AND draft history both dispensable HERE.
3. Efficiency (the item-2 question): LONG-ZERO total ≈ 308ms vs
   LONG-FULL ≈ 1885ms vs LONG-FRESH 1866.6ms — ~6x faster than fresh
   WITH drafting active, in v2, no format change. Per-size totals:
   short ≈ 244ms vs 685ms control; divergent 391ms tail-only vs full-78.
4. Cross-build determinism: LONG-ZERO text (rev234) byte-identical to
   LONG-FULL text (rev233); T1-longgen text identical across rev233 builds.
5. Divergent tails survive zero-carry: (1,42,36,78) partial reuse, 5/7
   accepts — slightly below same-prefix rates; needs broader validation.

## What this changes (and does not)

- The harvest cost floor applied to the HARVEST FAMILY only. M3 shows a
  harvest-free v2 path with ~zero rebuild cost on tested prompts.
- v3 necessity REVISED: v3 (mirror blob) is no longer the only way — it
  is now the FALLBACK if M3 fails to generalize. M3-first.
- NOT proven: general validity (prompt families, longer generations,
  deep-prefix discrimination, code prompts); productization needs the
  flag removed + a principled load path + acceptance-watch fallback +
  full Final gates. M3 productization is PRESENTED as the minimal
  alternative — NOT implemented, awaits authorization like v3.
- Evidence: slots-rev211/T3-M3 + T3b-M3x (JSONs + slice.log per arm).
